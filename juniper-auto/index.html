Cinqic research / Juniper Auto

One model. Many questions.

Juniper Auto is an open, consumer-scale research project exploring whether one approximately 150-million-parameter sparse Mixture-of-Experts language model can become capable, local, customizable, and autonomous on practical hardware.

Phases 0–2 approved · Phase 3 candidate pending independent review

Open the canonical repository ↗Back to Research

01 — Current status

Foundation and architecture work, not a finished model.

Phase 0 established the research charter, governance, reproducibility, frozen configuration, validation, and recovery foundation. Phase 1 implemented the sparse and dense reference architectures and training plumbing. Phase 2 independently approved the routing, dispatch, diagnostics, ablation, and context-sensitivity infrastructure.

Phase 3 has produced a candidate unified UTF-8 byte-level BPE tokenizer. It is tokenizer engineering only; it has not been independently reviewed or approved.

02 — Architecture

Implemented as research software, not yet trained into a capability.

The repository contains a sparse architecture and a mandatory dense control so the cost and value of routing can be measured honestly.

Sparse target

150,031,360 parameters

Approximately 150M total; approximately 79,252,480 standard active parameters.

Dense control

79,191,040 parameters

A same-stack dense comparison model for evaluating whether sparsity earns its complexity.

Current context

4,096 tokens

The repository’s current supported context; the larger future target is not advertised as implemented.

03 — Research question

Can a single small model learn many roles without becoming a collection of specialists?

Juniper Auto treats internal specialization as a property to measure inside one routed model. The project is not claiming that the model is already autonomous, expert, or generally capable.

05 — Explicit non-claims

What does not exist yet.

No model has been trained on real data. There is no base or instruction-tuned checkpoint, no real pretraining corpus, no autonomy runtime, no tools, no persistent memory system, and no demonstrated expert specialization.

  • Tokenizer: candidate only; no model runtime is implied.
  • Architecture: executable and validated; language capability is not implied.
  • Availability: research source only; no consumer download is offered.
