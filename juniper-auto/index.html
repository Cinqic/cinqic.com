Juniper Auto

One small, open, consumer-scale sparse Mixture-of-Experts language model — intended to converge many general and autonomous capabilities into one model, not a coordinated collection of specialists.

Phase 0 research foundation independently reviewed and approved, with documented accepted limitations

Planned launch: October 1, 2026.

Open the canonical repository ↗ View architecture

01 — Current status

Foundation engineering, not model training.

Phase 0 established the research charter and governance rules, the frozen ja150m-v0.1 and ja150m-v0.1-dense architecture configurations (schema-validated and independently parameter-counted), a deterministic seed framework, structured logging, an ADR system, an experiment registry, engineering time accounting, a frozen-artifact manifest with SHA-256 hashes, repository validation, CI, and a tested clean-machine recovery procedure.

Phase 0 also built FoundationProbe, a minimal tensor-pipeline smoke test used only to prove imports, config loading, seeding, and reproducibility work end to end. FoundationProbe is not the Juniper Auto model.

No tokenizer, training dataset, trained checkpoint, inference runtime, persistent memory system, or tool-use system currently exists. Model implementation begins in a later phase.

02 — Research question

Testing the limits of small autonomous intelligence.

How capable, efficient, autonomous, persistent, adaptable, reliable, and meaningfully self-improving can one approximately 150-million-parameter open sparse Mixture-of-Experts language model become while remaining practical on consumer hardware and genuinely customizable? The project is not merely building another chatbot — it is asking whether a single small model can learn to serve many roles at once.

03 — One model

One cognitive model. Internal specialization through learned routing.

Juniper Auto is not intended to permanently consist of separate math, coding, research, productivity, and creativity language models coordinated by an orchestrator. It is designed to explore whether one small sparse Mixture-of-Experts model can learn, through its own routing, to specialize internal computation appropriately across many domains — language, coding, mathematics, research reasoning, and beyond — inside a single set of weights.

This one-model philosophy is foundational to the project: no permanent collection of separate specialist models, coordinated by an orchestrator.

04 — Frozen architecture

Target architecture. Not yet trained.

150,031,360 total parameters

The frozen ja150m-v0.1 configuration is a decoder-only causal sparse Mixture-of-Experts Transformer. Parameter counts are independently derived by code and asserted by tests on every run — not hand-transcribed. No model built to this configuration has been trained yet.

05 — Sparse vs. dense research

Evidence, not architectural fashion.

Juniper Auto includes a mandatory dense research control, ja150m-v0.1-dense (79,191,040 parameters, all-dense, no sparsity), to determine whether the sparse MoE architecture’s added complexity actually earns its keep. Active-parameter counts are not assumed to equal measured FLOPs, latency, or runtime cost — the project distinguishes parameter accounting from measured compute efficiency, and no comparison results exist yet.

06 — Capability targets

Research targets, not demonstrated capabilities.

Eventual research targets include competence across the areas below, converged into one model through learned routing. None of these are currently demonstrated — no model has been trained.

01

Language & coding

Natural-language instruction following and coding, as a foundation for everything else.

02

Math & research

Mathematics, research-oriented reasoning, and structured information synthesis.

03

Productivity & creativity

Practical productivity assistance alongside open-ended creative work.

04

Planning & tools

Planning, tool selection and use, tool-result interpretation, and verification.

05

Recovery

Failure recovery and honest interpretation of its own state.

06

Memory & autonomy

Memory-use decisions and bounded autonomous-control decisions.

07 — Local and consumer scale

Built to run on hardware people actually own.

Juniper Auto is deliberately constrained around consumer hardware. The current baseline development machine, FLOWBOX, is a Ryzen 7 5700G, RTX 2060 (6GB VRAM), 16GB RAM, 256GB NVMe, and 500GB HDD — an engineering baseline, not a promise that every future training run happens exclusively on this one machine.

The important public principle: Juniper Auto must not quietly evolve into something that requires datacenter hardware merely to perform core inference. The project is also local-first — core future goals include useful local inference, conversation state, memory, file access, and compatible tools. Cloud services may eventually accelerate training or evaluation, but are not intended to become a mandatory dependency for basic model use.

08 — Autonomy

A future runtime target, not a current capability.

The eventual Juniper Auto runtime is intended to explore objective management, persistent state and memory, tool permissions and a tool registry, sandboxed execution, scheduling, event handling, resource limits, process supervision, checkpoint/resume, action logging, interruption, rollback, and iterative reason → act → observe → verify → revise → continue behavior. The project is investigating whether a small language model can eventually serve as assistant, planner, tool user, verifier, critic, researcher, programmer, and autonomous controller without relying on permanent specialist language models. None of this runtime is implemented yet.

09 — Open and customizable

Inspectable, modifiable, forkable, retrainable.

Juniper Auto is intended to remain inspectable, modifiable, forkable, retrainable, and customizable. The repository currently ships an MIT license. Whether that license also applies to the final trained weights, tokenizer, and training datasets is an open governance matter that has not yet been decided — this page does not claim a final licensing decision has been made for those future artifacts.

Explicit v0.1 non-goals

Deliberately bounded scope.

v0.1 explicitly excludes native image encoding, native audio encoding, native speech synthesis, native video understanding, architectural recurrence, adaptive neural halting, hierarchical MoE, dynamic expert creation during normal inference, unrestricted self-modification, automatic promotion of self-generated checkpoints, and permanent specialist-model collections. External perception or multimodal capabilities may eventually be provided through external tools and adapters rather than by consuming the 150M language-model parameter budget. Juniper Auto is not currently multimodal.
